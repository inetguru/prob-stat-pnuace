# HW — 생일 문제 (Birthday Problem)

**확률통계 · Topic 1** | 배점 25점 | 개인 과제

---

## 배경

같은 강의실에 $n$명이 있다. **생일이 같은 사람이 적어도 두 명 있을 확률**은 얼마일까?

대부분의 사람은 "50%가 되려면 180명쯤 필요하지 않나"라고 답한다.
실제로는 **23명**이면 이미 50%를 넘는다. 직관과 계산이 어긋나는 대표적인 사례다.

이 문제는 컴퓨터과학에서 **hash collision**과 정확히 같은 구조다.
버킷이 365개인 해시 테이블에 키를 $n$개 넣을 때 충돌이 일어날 확률과 같은 계산이다.

> **가정** — 1년은 365일(윤년 무시), 모든 날짜의 출생 확률이 동일하다.
> 실제 출생일 분포는 균등하지 않다. 이 가정에 대해서는 문제 4에서 생각해본다.

---

## 문제

### 1. 시뮬레이션 (8점)

$n = 2, 3, \ldots, 60$ 각각에 대해 **생일이 겹치는 사람이 있을 확률**을 시뮬레이션으로 추정한다.

- 각 $n$마다 최소 **10,000회** 반복할 것
- 난수 생성기는 `np.random.default_rng(20260302)` 로 시작할 것 (재현성)
- 힌트: `rng.integers(0, 365, size=n)` 로 $n$명의 생일을 만들고,
  `np.unique(...)` 의 길이가 $n$보다 작으면 겹친 것이다

### 2. 이론값 (7점)

같은 $n$ 범위에서 이론값을 계산한다.

$$
\mathbb{P}[\text{적어도 두 명 일치}] \;=\; 1 - \frac{365 \times 364 \times \cdots \times (365-n+1)}{365^{\,n}}
$$

- 랩 노트북 **부록 A**의 `math.perm` 을 쓰면 한 줄이다
- $n > 365$ 일 때 이 식이 어떻게 되는지도 생각해볼 것 (제출 불필요)

### 3. 그래프 (5점)

시뮬레이션 결과와 이론값을 **하나의 그래프에 겹쳐** 그린다.

- x축: 사람 수 $n$ / y축: 확률
- 시뮬레이션은 점 또는 옅은 선, 이론값은 실선으로 구분
- $y = 0.5$ 에 수평 기준선을 긋고, **50%를 넘는 최소 $n$** 을 그래프 위에 표시
- 축 이름·제목·범례를 **영어로** 반드시 붙일 것 (Colab 한글 폰트 문제)

### 4. 해석 (5점)

다음 두 가지를 **각각 3문장 이내**로 노트북 마지막 마크다운 셀에 작성한다.

- **(a)** 이 문제를 여사건("모두 생일이 다르다")으로 계산하는 것이 왜 더 쉬운가?
  직접 계산하려면 무엇을 해야 하는지와 비교해서 설명할 것.
- **(b)** "모든 날짜의 출생 확률이 같다"는 가정이 깨지면 (예: 특정 계절에 출생이 몰림)
  일치 확률은 **커질까 작아질까?** 직관적인 이유를 쓸 것. (증명은 요구하지 않는다)
