데이터를 나눈다는 것

확률통계 · Topic 1 보충자료 — 슬라이드 32번 "오늘 배운 게 어디에 쓰이나" 의 Data sampling

슬라이드에서 "mini-batch, train/test split, cross-validation이 전부 표집 문제이다" 라고만 하고 지나갔다. 이 셋은 머신러닝을 배우면 첫 주에 만나는 말인데, 정작 왜 그렇게 하는지는 확률을 모르면 설명이 안 된다.

이 문서는 셋이 각각 무엇인지, 그리고 셋이 왜 같은 이야기의 세 얼굴인지를 보인다. 머신러닝을 몰라도 읽을 수 있게 썼다. 시험 범위가 아니다.

미리 말해 둘 것 — 이 문서에 "모델"이라는 말이 나오면 입력을 받아 답을 내놓는 상자 정도로 읽으면 된다. 안에서 무슨 일이 벌어지는지는 전혀 몰라도 이 글은 이해된다.

1. 셋은 사실 한 가지 이야기다

Topic 1에서 우리는 전체를 Ω 라 부르고, 실제로 관찰한 것은 그중 일부라는 구도를 세웠다. 동전을 무한히 던질 수는 없어서 1,000번만 던졌고, 그래서 0.5가 아니라 0.475가 나왔다.

머신러닝에서 데이터를 다루는 방식은 전부 이 구도의 반복이다. 전체를 볼 수 없거나, 봐서는 안 되거나, 한 번 봐서는 못 믿을 때 일부를 뽑는다.

이름무엇을 뽑나왜 뽑나
train/test split 가진 데이터를 두 덩이로 봐서는 안 되는 것을 따로 떼어 둔다 — 시험문제를 미리 보면 안 되니까
mini-batch 학습용 데이터에서 매번 조금씩 전부 보면 너무 느리다 — 일부로 방향만 잡는다
cross-validation 나누는 방식 자체를 여러 번 한 번 재고는 못 믿는다 — 여러 번 재서 평균한다
세 줄을 한 줄로 줄이면 이렇다 — 일부만 보면 값이 흔들린다. 그 흔들림을 관리하는 세 가지 방법이다. Topic 1 오프너에서 본 "다섯 번 다 다른 궤적" 이 여기서 다시 나온다.

2. train/test split — 시험문제를 미리 보면 안 된다

모델을 만들 때 데이터가 1,000개 있다고 하자. 1,000개를 전부 써서 모델을 만들고, 같은 1,000개로 성적을 매기면 어떻게 될까?

거의 항상 아주 좋은 점수가 나온다. 그리고 그 점수는 아무 의미가 없다. 1,000개를 통째로 외워버린 모델도 만점을 받기 때문이다. 우리가 알고 싶은 것은 "외운 것을 되뇌는 능력"이 아니라 처음 보는 데이터에 대해서도 맞히는 능력 이다.

이렇게 하면 안 된다 1,000개로 배우고 같은 1,000개로 채점
기출문제를 통째로 외운 학생에게 그 기출문제로 시험을 치는 것과 같다. 점수는 높지만 실력을 잰 것이 아니다.
이렇게 한다 800개로 배우고, 숨겨둔 200개로 채점
200개는 학습 중에 한 번도 보여주지 않는다. 이 200개에서 나온 점수라야 "처음 보는 것에 대한 실력" 이다.

숨겨두는 쪽을 test set, 배우는 데 쓰는 쪽을 train set 이라고 부른다. 비율은 보통 8:2 나 7:3 을 쓴다.

그런데 어떻게 나눌 것인가

여기서 Topic 1이 필요해진다. "그냥 앞에서부터 800개" 로 자르면 될까? 안 된다. 데이터가 어떤 순서로 저장돼 있는지 우리는 모르기 때문이다.

아래에서 직접 확인해 보자. 데이터 20개가 있고, 절반은 A 종류(파랑), 절반은 B 종류(분홍) 이다. 그런데 파일에 A 가 먼저, B 가 나중에 저장돼 있다 — 실제 데이터셋에서 아주 흔한 일이다. 라벨 순으로 정리해 두는 경우가 많으니까.

시연 ① — 어떻게 자르느냐가 결과를 바꾼다

20개를 14 : 6 (70:30) 으로 나눈다
전체 데이터 (파일에 저장된 순서)
TRAIN — 배우는 데 쓴다
TEST — 숨겨두고 채점에만 쓴다

그대로 자르면 train 에는 A 가 10개 · B 가 4개, test 에는 A 가 0개 · B 가 6개가 된다. 이 test set 으로는 "A 를 맞히는 능력"을 아예 측정할 수 없다. 모델이 A 를 전부 틀려도 점수에 반영되지 않는다. 점수는 나오지만 거짓말이다.

섞은 다음 자르면 두 쪽 모두 A 와 B 가 대략 반반 섞인다. train 과 test 가 같은 성격의 데이터가 되고, 그제서야 점수가 의미를 가진다.

Topic 1의 언어로 말하면 이렇다 — 섞는 행위는 "모든 데이터가 test 로 뽑힐 확률을 같게" 만드는 장치 다. 슬라이드 27번에서 "등확률을 언제 써도 되나" 를 물었고 답이 "설계로 보장했을 때(무작위 추출)" 였다. 이게 바로 그 설계다.

3. 무작위로 섞어도 운이 나쁠 수 있다

섞으면 안전할까? 대체로 그렇지만 항상은 아니다. 20개 중 6개를 무작위로 골랐을 때, 하필 6개가 전부 B 일 수도 있다. 그 확률을 Topic 1의 도구로 직접 셀 수 있다.

ℙ[test 6개가 전부 B]  =  C(10, 6) / C(20, 6)  =  210 / 38,760  ≈  0.0054
← C(n, r) 은 n 개에서 r 개를 고르는 가짓수

약 185번에 한 번이다. 드물지만 0은 아니다. 데이터가 적을수록, 그리고 한쪽 종류가 희귀할수록 이 확률은 커진다. 그래서 실제 도구에는 계층 표집(stratified sampling) 이라는 장치가 따로 있다 — "A 와 B 의 비율을 train 과 test 에서 똑같이 맞춰라" 는 뜻이다.

여기가 이 과목의 쓸모다. "섞으면 되겠지" 와 "섞어도 185번에 한 번은 이런 일이 난다" 는 전혀 다른 수준의 이해다. 뒤쪽을 말할 수 있으려면 여사건 · 조합 · 등확률 가정이 필요하다 — 전부 Topic 1에서 배운 것이다.

4. mini-batch — 전부 보지 않고 방향을 정한다

모델을 학습시킨다는 것은, 아주 거칠게 말하면 이런 반복이다.

① 지금 얼마나 틀리는지 잰다  →  ② 덜 틀리는 쪽으로 조금 고친다  →  ① 로 돌아간다

문제는 ①이다. 데이터가 100만 개면 한 번 재는 데 100만 번의 계산이 든다. 그걸 수천 번 반복해야 하니 감당이 안 된다.

그래서 이렇게 한다 — 매번 전부 재지 않고, 무작위로 32개만 뽑아서 잰다. 이 32개 묶음이 mini-batch 다. 100만 번이 32번으로 줄어든다.

싸게 얻은 만큼 흔들린다

당연히 공짜가 아니다. 32개로 잰 값은 100만 개로 잰 값과 다르다. 얼마나 다를까? 이것이 정확히 Topic 1 오프너에서 본 그림이다. 아래에서 배치 크기를 바꿔 가며 직접 확인해 보자.

시연 ② — 배치가 작을수록 크게 흔들린다

1 = 맞힘 · 0 = 틀림 · 데이터 24개

배치 크기를 2 로 두고 돌려 보면 배치 평균이 0 과 1 사이를 마구 오간다. 24 로 두면 배치가 하나뿐이고 그 값은 참값과 정확히 같다. 중간값들은 그 사이 어딘가다.

흔들림의 크기는 계산할 수 있다. 값이 0 또는 1 이고 참 비율이 0.5 일 때, 배치 n 개로 잰 평균의 표준편차는 다음과 같다.

배치 n 개로 잰 평균의 표준오차  =  σ / √n  =  0.5 / √n
배치 크기 n41664256
흔들림 (표준오차)0.2500.1250.06250.0312

※ 위 표는 데이터가 아주 많을 때의 값이다. 시연 ②는 데이터가 24개뿐이라 배치를 키울수록 "아직 안 뽑은 것"이 빠르게 줄어들고, 그래서 표시되는 이론값이 이 표보다 조금 작다. 배치 24에서는 배치가 곧 전체이므로 흔들림이 정확히 0 이 된다.

배치를 4배 키우면 흔들림은 절반으로 준다. 4배가 아니라 2배다 — √n 이 분모에 있기 때문이다. Topic 1 슬라이드 7번에서 본 0.159 → 0.050 → 0.016 이 똑같은 법칙이다. (n 이 10배일 때 √10 ≈ 3.16 배 줄어 대략 1/3.)

이 √n 법칙이 배치 크기를 정하는 실무의 근거다. 배치를 4배 키우면 계산은 4배 비싸지는데 정확도는 2배밖에 안 좋아진다. 어디서 멈출 것인가가 곧 트레이드오프다. 왜 하필 √n 인지는 Topic 10 에서 증명한다.

흔들림이 나쁘기만 한 것은 아니다. 조금 부정확한 방향으로 움직이는 덕분에 모델이 엉뚱한 곳에 갇히지 않고 빠져나오기도 한다. 그래서 실무에서는 배치를 일부러 아주 크게 잡지 않는다. 다만 이 이야기는 확률통계의 범위를 넘어간다 — 최적화 과목의 몫이다.

5. cross-validation — 한 번 재고 믿지 않는다

2절로 돌아가자. 데이터 100개를 80 : 20 으로 나눠 test 20개에서 85점을 받았다고 하자. 이 85점을 얼마나 믿을 수 있을까?

test 가 20개뿐이라는 게 문제다. 20개는 그 자체로 작은 표본이고, 4절에서 본 그대로 작은 표본에서 잰 값은 흔들린다. 모델의 진짜 실력이 85% 라 해도, 어떤 20개를 뽑았느냐에 따라 점수는 이만큼 오르내린다.

√( 0.85 × 0.15 / 20 )  =  0.080   ⟹   점수는 약 ± 8 %p 오르내린다

85점이 사실은 77점일 수도, 93점일 수도 있다는 뜻이다. 이 정도 오차로는 "모델 A 가 모델 B 보다 낫다" 같은 판단을 할 수 없다.

데이터를 더 구할 수 없다면

가진 게 100개뿐이라면 test 를 키울 수 없다. test 를 40개로 늘리면 train 이 60개로 줄어 모델 자체가 나빠진다. 딜레마다.

해법은 발상의 전환이다 — 나누는 방식을 하나로 고정하지 말고, 돌려가면서 여러 번 하자. 데이터를 k 덩이로 쪼갠 뒤, 한 덩이씩 돌아가며 test 역할을 맡긴다. 이것이 k-fold cross-validation 이다.

시연 ③ — 돌아가며 채점한다

데이터 15개 · ● 맞힘 · ✕ 틀림

돌려 보면 개별 fold 의 점수는 크게 튄다. 5-fold 면 한 fold 가 3개뿐이라 점수가 0, 0.333, 0.667, 1.000 네 가지 중 하나로만 나온다. 그런데 평균은 언제나 0.800 이다. k 를 3으로 바꿔도 평균은 그대로 0.800 이다.

왜 항상 같은가? 모든 데이터가 정확히 한 번씩 test 를 거치기 때문이다. 덩이 크기가 같으면 fold 점수들의 평균은 "전체 15개를 한 번씩 채점한 결과"와 수학적으로 똑같다. test 를 20개가 아니라 100개 전부로 쓴 셈이 된다.

그래서 흔들림이 줄어든다. 100개 데이터로 5-fold 를 하면 실질적으로 100개 전부에서 채점한 것이므로,

방식실질 채점 대상점수의 흔들림
한 번만 80:20 으로 나누기20개± 8.0%p
5-fold cross-validation100개 전부± 3.6%p

같은 100개 데이터인데 흔들림이 2.24배 차이난다. 데이터를 한 개도 더 구하지 않고 얻은 개선이다. 대가는 계산량이다 — 모델을 k 번 학습시켜야 하므로 k 배 느리다.

덧 — 위 표의 3.6%p 는 다소 낙관적인 값이다. k 개의 fold 점수는 서로 완전히 독립이 아니기 때문이다 (train set 이 서로 겹친다). 그래도 한 번만 나누는 것보다 훨씬 안정적 이라는 결론은 바뀌지 않는다. 이 "독립이 아니다" 라는 말의 정확한 의미는 Topic 9 에서 다룬다.

6. 셋을 한 장으로

train/test split mini-batch cross-validation
언제 학습을 시작하기 전 한 번 학습 도중 매 순간 모델을 평가할 때
왜 정직한 채점지를 확보하려고 계산을 감당하려고 점수를 믿을 만하게 만들려고
무작위성의 역할 두 덩이의 성격을 같게 만든다 치우친 방향으로 가지 않게 한다 모든 데이터에 채점 기회를 준다
흔들리는 것 측정된 점수 고칠 방향 (줄이는 것이 목적)
줄이는 법 test 를 키운다 배치를 키운다 k 를 키운다
다섯 줄이 전부 같은 문장의 변주다 — 표본이 크면 흔들림이 작다. 대신 비싸다. 이 한 문장이 데이터를 다루는 거의 모든 결정의 뒤에 있다.

7. 흔한 실수 네 가지

실수 1 test 를 보면서 모델을 고친다
test 점수를 보고 설정을 바꾸고, 다시 재고, 또 바꾼다. 이러면 test 도 결국 train 이 되어버린다. 답을 보면서 공부한 셈이다.
→ 그래서 보통 train / validation / test 셋으로 나눈다. 고치는 동안은 validation 만 보고, test 는 맨 마지막에 딱 한 번 연다.
실수 2 나누기 전에 데이터를 손본다
1,000개 전체의 평균으로 정규화한 다음 나누면, test 의 정보가 이미 train 에 스며든다. 점수가 실제보다 좋게 나온다.
→ 먼저 나누고, train 에서 계산한 값만 test 에 적용한다. 이런 정보 누출을 data leakage 라고 부른다.
실수 3 시간 순서가 있는 데이터를 무작위로 섞는다
주가·기상·로그처럼 시간 순서가 있는 데이터를 섞어 나누면 미래를 보고 과거를 맞히는 모델이 된다. 점수는 훌륭하고 실전에서는 무용지물이다.
→ 시계열은 시점으로 자른다. 앞이 train, 뒤가 test.
실수 4 배치를 섞지 않고 순서대로 먹인다
데이터가 라벨 순으로 정렬돼 있으면, 배치 하나에 같은 종류만 들어간다. A 만 잔뜩 보다가 B 만 잔뜩 보게 되니 방향이 갈지자로 요동친다.
→ 매 에폭마다 다시 섞는다. 시연 ②의 "1 에폭 실행" 이 매번 섞는 이유다.

네 가지가 전부 같은 실수의 변형이다 — test 로 쓸 것과 train 으로 쓸 것의 경계를 흐리는 것. 경계가 한 번 흐려지면 그 뒤에 나오는 모든 숫자를 믿을 수 없게 된다.
