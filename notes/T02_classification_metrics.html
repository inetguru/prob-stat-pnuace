정확도 99% 의 함정

확률통계 · Topic 2 보충자료 — 슬라이드 7번 (10만 명을 직접 세어 본다) · 30번 (→AI 연결점)

슬라이드 30번에서 "accuracy 대신 PPV · recall · F1 을 보는 이유가 오늘 그림에 있다" 라고만 하고 지나갔다. 그 말이 무슨 뜻인지 여기서 끝까지 본다.

⚠️ 이 문서에 새 확률 개념은 없다. 등장하는 모든 척도가 조건부 확률 하나다. 달라지는 것은 무엇을 조건으로 거느냐 뿐이다. Topic 2 의 핵심 문장 — "방향을 바꾸면 다른 값이 된다" — 이 그대로 반복된다.

1. 게으른 모델이 좋은 검사를 이긴다

슬라이드 6~7번의 상황을 다시 가져온다. 유병률 0.1%, 민감도 99%, 특이도 99%. 10만 명을 검사하면 이렇게 된다.

이 검사의 정확도(accuracy) 를 재 보자. 맞힌 사람 수를 전체로 나누면 된다.

Accuracy = (99 + 98,901) / 100,000 = 0.9900  →  99.00%

훌륭해 보인다. 그런데 여기 아무 일도 안 하는 프로그램을 하나 만들어 보자. 검사 결과를 보지도 않고 모두에게 "음성"이라고 답하는 한 줄짜리 코드다.

def 진단(사람): return "음성"

Accuracy = 99,900 / 100,000 = 0.9990  →  99.90%
99% 짜리 검사보다 0.9%p 더 정확하다.
⚠️ 환자를 단 한 명도 못 찾는 프로그램이 정확도 1등이다. accuracy 는 드문 것을 무시할수록 올라간다. 희귀한 것을 찾는 문제에서 이 수는 아무것도 말해 주지 않는다.

이것을 클래스 불균형(class imbalance) 문제라고 한다. 스팸 탐지, 부정거래 탐지, 희귀질환 스크리닝, 불량품 검출 — 중요한 쪽이 드문 문제는 전부 여기에 해당한다. 그래서 척도를 여러 개 봐야 한다.

2. 혼동행렬 — 네 칸으로 나눠 본다

accuracy 는 맞힌 것과 틀린 것 두 덩어리로만 나눈다. 그런데 틀리는 방식에는 두 종류가 있고, 그 둘의 대가가 전혀 다르다. 네 칸으로 나눈 표를 혼동행렬(confusion matrix) 이라고 한다.

실제 환자 실제 건강
검사 결과 양성
TP99제대로 찾아냄
FP999헛놀람 · 오탐

FN1놓침

이름 읽는 법 — 뒷글자가 예측, 앞글자가 맞았는지

뒷글자 = 내가 뭐라고 했나 Positive → "양성이다"라고 말했다
Negative → "음성이다"라고 말했다
앞글자 = 그 말이 맞았나 True → 맞았다
False → 틀렸다

그래서 FP 는 "양성이라고 했는데 틀렸다" = 건강한 사람을 환자라고 했다. FN 은 "음성이라고 했는데 틀렸다" = 환자를 놓쳤다.

Topic 14 에서 이 두 칸을 다시 만난다. 가설검정에서 FP 는 제1종 오류(Type I error, α), FN 은 제2종 오류(Type II error, β) 라는 이름을 얻는다. 아래에서 볼 Recall 은 검정력(power) = 1 − β 와 같은 값이다. 지금 세는 네 칸이 Topic 14 의 뼈대다.

3. 네 칸에서 나오는 척도들 — 전부 조건부 확률이다

중요한 것은 공식이 아니라 무엇으로 나누느냐 다. 나누는 수(분모)가 곧 조건이다.

이름계산 조건부 확률로 쓰면무엇을 묻는 말인가
Recall
= 민감도 · TPR		 TP / (TP+FN)
99 / 100		 ℙ[양성 | 환자] 환자를 몇 %나 찾아냈나
놓친 환자가 얼마나 되나
Precision
= PPV		 TP / (TP+FP)
99 / 1,098		 ℙ[환자 | 양성] 양성이라 한 것 중 몇 %가 진짜였나
헛놀람이 얼마나 되나
Specificity
= TNR		 TN / (TN+FP)
98,901 / 99,900		 ℙ[음성 | 건강] 건강한 사람을 몇 %나 제대로 넘겼나
NPV TN / (TN+FN)
98,901 / 98,902		 ℙ[건강 | 음성] 음성이라 한 것 중 몇 %가 진짜 건강한가
Accuracy (TP+TN) / 전체 ℙ[맞힘] 조건이 없다 — 그래서 드문 쪽이 묻힌다
⭐ 오늘의 두 방향이 여기 그대로 있다

Recall = ℙ[양성 | 환자] = 0.99  — 검사 성능. 제조사가 광고하는 수
Precision = ℙ[환자 | 양성] = 0.09  — 내 걱정. 내가 알고 싶은 수
같은 검사인데 0.99 와 0.09. 슬라이드 11번의 "방향을 바꾸면 다른 값이 된다"가 바로 이것이다.

이 둘을 잇는 것이 Bayes 정리다. Precision 을 Bayes 로 풀어 쓰면 이렇게 된다.

Precision = Recall × 유병률  /  ( Recall × 유병률 + (1−Specificity) × (1−유병률) )
= 0.99×0.001 / (0.99×0.001 + 0.01×0.999) = 0.00099 / 0.01098 = 0.0902

Recall 과 Specificity 는 검사만 보면 정해지는데, Precision 은 유병률까지 알아야 정해진다. 검사 성능이 그대로여도 어디에 쓰느냐에 따라 값이 통째로 달라진다는 뜻이다. 아래 시연에서 유병률만 움직여 보면 바로 보인다.

4. Precision 과 Recall 은 서로 싸운다

실제 분류기는 "양성/음성"을 바로 내놓지 않는다. 0 과 1 사이의 점수를 내놓고, 우리가 임계값(threshold) 을 정해 자른다. 이 선을 어디에 긋느냐가 Precision 과 Recall 을 정한다.

선을 낮추면 의심스러우면 다 양성
환자를 거의 안 놓친다 → Recall ↑
대신 헛놀람이 쏟아진다 → Precision ↓
선을 높이면 확실할 때만 양성
양성이라 하면 대체로 맞는다 → Precision ↑
대신 환자를 놓친다 → Recall ↓

둘을 동시에 올릴 수는 없다. 하나를 얻으면 하나를 내준다. 그래서 "이 모델의 성능은 얼마인가" 라는 질문에는 답이 하나로 나오지 않는다. 어디에 선을 그었는지를 같이 말해야 한다.

5. F1 — 왜 그냥 평균을 안 쓰나

Precision 과 Recall 두 개를 계속 들고 다니기 번거로우니 하나로 합치고 싶다. 그런데 보통의 평균(산술평균)을 쓰면 안 된다. 이유를 숫자로 본다.

스팸 메일 1,000통 중 딱 1통만 스팸이라고 판정하는 극단적으로 소심한 필터를 생각하자. 그 1통이 진짜 스팸이면 Precision 은 1.000 — 완벽하다. 하지만 스팸 1,000통 중 1통만 잡았으니 Recall 은 0.001 이다.

산술평균 = (1.000 + 0.001) / 2 = 0.5005   ← 쓸모없는 필터가 "절반은 한다"는 점수를 받는다

조화평균 (F1) = 2 × (1.000 × 0.001) / (1.000 + 0.001) = 0.0020   ← 정직하다
F1 = 2 · Precision · Recall / (Precision + Recall)

조화평균은 작은 쪽에 끌려간다. 둘 중 하나라도 0 에 가까우면 F1 도 0 에 가까워진다. "둘 다 어느 정도는 해야 점수를 준다" 는 뜻이다. 산술평균처럼 한쪽을 극단으로 밀어 점수를 따는 편법이 통하지 않는다.

마지막 줄을 보라. 그 검사의 Accuracy 는 0.990 인데 F1 은 0.165 다. 같은 검사에 대한 두 점수의 차이가 이 문서 전체의 요점이다.

⚠️ F1 도 만능은 아니다. F1 은 TN 을 아예 쓰지 않는다. 네 칸 중 세 칸(TP·FP·FN)만 본다. "제대로 넘긴 건강한 사람"이 몇 명이든 F1 은 안 바뀐다. 드문 쪽을 찾는 문제에서는 그게 장점이지만, 두 부류가 비슷하게 많은 문제에서는 오히려 정보를 버리는 셈이다.

한쪽을 더 무겁게 — Fβ

놓치는 것이 훨씬 위험한 상황(암 검진)에서는 Recall 에 가중치를 준다.

Fβ = (1+β²) · P · R / (β²·P + R)
β = 1 → F1 (똑같이 중요)  ·  β = 2 → Recall 을 2배 무겁게 (놓치면 큰일)  ·  β = 0.5 → Precision 을 2배 무겁게 (헛놀람이 비쌀 때)

위 검사(P=0.090, R=0.990) 에 적용하면 — F0.5 = 0.110  ·  F1 = 0.165  ·  F2 = 0.330

6. 그래서 무엇을 봐야 하나

정답은 "상황에 따라 다르다" 이고, 그 상황을 정하는 것은 통계가 아니라 틀렸을 때 누가 무엇을 잃는가 다.

상황더 아픈 실수주로 보는 척도
스팸 필터 FP — 중요한 메일이 스팸함으로 간다. 면접 결과 메일을 놓치면 스팸 몇 통 받는 것과 비교가 안 된다. Precision 우선. 확실할 때만 스팸으로. F0.5
암 1차 검진 FN — 환자를 놓친다. 헛놀람은 재검사로 풀리지만 놓친 암은 되돌릴 수 없다. Recall 우선. 의심되면 다 양성. F2
부정거래 탐지 둘 다. 놓치면 손해, 막으면 정상 고객이 불편하다. F1 · 비용을 금액으로 환산해 비교
두 부류가 비슷하게 많을 때 특별히 한쪽이 아프지 않다. Accuracy 로 충분하다. 불균형이 없으면 함정도 없다
⭐ 실무의 순서는 이렇다. ① 두 종류의 실수 중 어느 쪽이 더 비싼지 먼저 정한다 → ② 그에 맞는 척도를 고른다 → ③ 임계값을 그 척도가 좋아지도록 조정한다. 모델을 바꾸기 전에 임계값부터 본다. 시연 ② 에서 봤듯 같은 모델도 선을 어디에 긋느냐로 성능이 완전히 달라진다.

7. 한 장으로 정리

하지 말 것
  • Accuracy 하나만 보고 판단하기
  • 드문 것을 찾는 문제에 Accuracy 쓰기
  • Precision 과 Recall 을 산술평균하기
  • 임계값을 안 밝히고 "성능 90%" 라고 말하기
할 것
  • 혼동행렬 네 칸을 먼저 본다
  • 더 비싼 실수가 무엇인지 정한다
  • Precision · Recall · F1 을 같이 본다
  • Precision 은 유병률이 바뀌면 같이 바뀐다는 것을 기억한다
한 줄 요약 — 모든 성능 척도는 조건부 확률이고, 무엇을 분모로 두느냐가 척도의 이름을 정한다. Recall 은 ℙ[양성 | 환자], Precision 은 ℙ[환자 | 양성]. Topic 2 가 내내 말한 "방향이 다르면 값도 다르다" 가 기계학습 평가의 첫 페이지에 그대로 적혀 있다.
