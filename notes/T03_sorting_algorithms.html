정렬 알고리즘과 평균 성능

확률통계 · Topic 3 보충자료 — 슬라이드 26번 (→AI 연결점) 의 "Quicksort의 평균 O(n log n)"

슬라이드는 "Quicksort의 평균 O(n log n)" 이라고만 적고 지나갔다. 그런데 이 한 줄에는 Topic 3 의 도구 두 개가 그대로 들어 있다 — 기댓값의 선형성(슬라이드 15)과 indicator(슬라이드 17).

이 문서가 답하는 것 세 가지
① 정렬 알고리즘 다섯 개는 각각 어떻게 움직이는가 (애니메이션으로 본다)
② Big-O 표기가 정확히 무슨 뜻인가
③ ⭐ "평균" O(n log n) 의 그 평균은 무엇의 평균이며 어떻게 유도되는가

1. 왜 정렬을 확률통계 수업에서 보는가

정렬 알고리즘의 성능은 입력이 어떻게 생겼느냐에 따라 달라진다. 그래서 성능을 말하려면 세 가지를 구분해야 한다.

최선 (best case) 가장 운이 좋을 때
이미 정렬된 배열이 들어오는 등. 거의 쓸모없는 정보다.
최악 (worst case) 가장 운이 나쁠 때
보장이 필요할 때 쓴다. 그런데 너무 비관적일 수 있다.
평균 (average case) ⭐ 기댓값
입력을 확률변수로 보고 비교 횟수의 기댓값을 구한다. 이게 오늘 배운 것이다.
평균 성능이란 정확히 이런 뜻이다

입력 배열을 무작위로 뽑는다고 하자 (n! 가지 순열이 모두 같은 확률).
C = 그때 알고리즘이 하는 비교 횟수  →  확률변수다 (슬라이드 10번).
평균 성능 = 𝔼[C]
"결과에 숫자를 대응시킨다"의 완벽한 예다 — Ω = 모든 입력 순열, C(순열) = 그 입력에서의 비교 횟수.

2. 다섯 알고리즘, 직접 돌려 본다

비교 0 교환·이동 0 n = 20 n² / 2 = 200 n log₂n = 86
알고리즘을 고르고 ▶ 실행을 누르라.

두 계수기의 뜻 — 비교는 두 값의 크기를 물어본 횟수, 이동은 값을 옮겨 쓴 횟수다. 둘은 같지 않다. 삽입 정렬을 n = 20 무작위 배열로 돌리면 비교는 약 111번, 이동은 약 114번이 나온다 (이동 = 역전 수 95 + 마지막에 제자리에 놓는 19번). §4 에서 유도하는 n(n−1)/4 = 95 는 "역전의 수" 다.

⚠️ 직접 해 볼 것 — "정렬된 배열로" 를 누르고 각각 돌려 보라.
삽입 정렬은 비교 n−1 번에 끝난다 (선형!). 선택 정렬은 그래도 n²/2 번을 다 센다.
퀵 정렬은 오히려 최악이 된다 — 이 문서의 마지막 절에서 이유를 설명한다.

왜 실무에서 퀵 정렬을 쓰나 — 병합 정렬은 최악에도 n log n 을 보장하는데도 퀵 정렬이 더 널리 쓰인다. 추가 메모리가 필요 없고(제자리 정렬), 한 번의 비교에 드는 실제 비용이 작기 때문이다. "보장은 나쁘지만 평균이 좋고 상수가 작다" — 평균을 믿고 가는 선택이다. Topic 3 이 내내 경고한 그 선택이기도 하다.

3. Big-O 표기 — 무엇을 재고 무엇을 버리는가

알고리즘의 속도를 초 단위로 말하면 컴퓨터가 바뀔 때마다 값이 달라진다. 그래서 입력 크기 n 이 커질 때 연산 횟수가 어떤 모양으로 자라는지만 본다. 그 모양을 적는 것이 Big-O 표기다.

f(n) = O(g(n)) 이란 —
n 이 충분히 커지면 f(n) ≤ c · g(n) 이 되는 상수 c 가 존재한다는 뜻.
쉽게 말해 "아무리 커져도 g 보다 빨리 자라지는 않는다" — 상한이다.

두 가지를 버린다

① 상수배를 버린다 3n² 도 100n² 도 그냥 O(n²)
컴퓨터가 100배 빨라지면 상수는 바뀐다. 모양은 안 바뀐다.
② 낮은 차수를 버린다 n² + 500n + 9999 도 O(n²)
n = 10,000 이면 n² = 1억. 500n = 500만. 큰 쪽이 다 먹는다.

마지막 줄을 보라. 100만 개를 정렬할 때 n log n 알고리즘이 0.02초면 끝낼 일을 n² 알고리즘은 약 17분 붙잡고 있다 (1초에 10억 번 비교한다고 치면). 알고리즘의 "모양"이 하드웨어보다 중요한 이유다.

세 곡선

n log₂ n 과 n² / 2 는 n 이 작을 때는 붙어 있다. 그래서 작은 배열에서는 삽입 정렬이 오히려 빠르다 (실제 라이브러리도 조각이 작아지면 삽입 정렬로 갈아탄다).

⚠️ Big-O 는 "얼마나 빠른가"가 아니라 "얼마나 잘 견디는가"다. O(n log n) 알고리즘이 n = 10 에서 O(n²) 보다 느릴 수 있다. Big-O 가 말하는 것은 n 이 커질 때 무슨 일이 벌어지는가 뿐이다.

세 기호 — O · Ω · Θ

기호뜻정렬에서의 예
O(g)상한 — 이보다 나쁘진 않다 퀵 정렬은 O(n²) — 최악에는 n² 까지 간다
Ω(g)하한 — 이보다 좋진 않다 비교 기반 정렬은 전부 Ω(n log n) — 아무리 잘 만들어도 못 넘는 벽이 있다
Θ(g)상·하한이 같다 병합 정렬은 Θ(n log n) — 입력이 무엇이든 이 값이다
Ω(n log n) 이라는 벽은 왜 있나 — 비교만으로 정렬하면 n 개의 순서로 가능한 경우가 n! 가지다. 비교 한 번은 답을 반으로 줄이므로 최소 log₂(n!) ≈ n log₂n − 1.44n 번은 비교해야 한다. 세는 문제로 바뀌었다 — Topic 1 의 셈하기가 여기서 쓰인다.

4. ⭐ 평균 성능을 기댓값으로 유도한다

여기서부터가 이 문서의 핵심이고, Topic 3 의 도구를 그대로 쓰는 곳이다. 방법은 하나다 — 슬라이드 17번의 indicator.

전략 — 세는 문제를 평균 문제로 바꾼다

① 비교 하나하나에 indicator 를 붙인다. Xij = 이 둘을 비교하면 1, 아니면 0
② 전체 비교 횟수 C = Σ Xij  — 모두 더한 것
③ 선형성으로 𝔼[C] = Σ 𝔼[Xij] = Σ ℙ[둘을 비교한다]
⭐ indicator 의 기댓값은 그 사건의 확률이다 — 𝔼[X] = 1·p + 0·(1−p) = p.
⭐ 독립일 필요가 없다. 비교들은 서로 심하게 얽혀 있는데도 그냥 더할 수 있다. 이게 선형성의 힘이다 (슬라이드 15번).

연습 ① 삽입 정렬 — 역전의 수가 평균 n(n−1)/4

삽입 정렬이 하는 일은 사실 "뒤집힌 쌍"을 하나씩 푸는 것이다. i < j 인데 ai > aj 이면 그 쌍을 역전(inversion) 이라 한다. 삽입 정렬이 값을 옆으로 미는 횟수는 정확히 역전의 개수다 — 한 번 밀 때마다 역전 하나가 풀린다.

Xij = 자리 i, j 의 두 원소가 뒤집혀 있으면 1

무작위 순열에서 두 원소 중 어느 쪽이 앞에 올지는 반반이므로   ℙ[뒤집힘] = 1/2

𝔼[역전 수] = Σi<j 1/2 = C(n,2) × 1/2 = n(n−1)/4
최악(역순 배열)은 n(n−1)/2 이니 평균은 정확히 그 절반이다. n = 20 이면 이론값 95.0 — 20만 번 모의실험한 실측이 94.95 였다.
⚠️ 비교 횟수는 이보다 약 n 만큼 많다(n = 20 에서 약 111). 밀지 않고 멈추는 마지막 비교가 원소마다 한 번씩 더 붙기 때문이다.
⚠️ 확률을 쓴 곳은 딱 한 줄이다 — ℙ[뒤집힘] = 1/2. 나머지는 전부 선형성으로 더한 것뿐이다. 쌍들이 서로 독립인지는 따지지 않았다. 따질 필요가 없다.

연습 ② 퀵 정렬 — 평균 2n ln n ≈ 1.39 n log₂n

퀵 정렬은 조금 더 재미있다. "어떤 두 원소가 서로 비교될 확률" 을 구하면 된다. 값을 크기 순으로 z1 < z2 < … < zn 라 하자.

핵심 관찰 — zi 와 zj 가 비교되는 것은 둘 사이의 값들 중 누가 먼저 pivot 이 되느냐로 정해진다.

· 사이의 값 zk (i<k<j) 가 먼저 pivot 이 되면 → 둘은 양쪽으로 갈라져 영영 만나지 않는다
· zi 나 zj 가 먼저 pivot 이 되면 → 그때 반드시 비교된다
구간 [zi … zj] 안에는 j − i + 1 개의 값이 있고, 그중 누가 먼저 pivot 이 되는지는 모두 같은 확률이다.
둘(zi, zj) 중 하나가 먼저일 확률은 —

ℙ[zi 와 zj 를 비교한다] = 2 / (j − i + 1)
⭐ 여기가 유일하게 확률을 쓴 곳이다. 멀리 떨어진 값일수록 비교될 확률이 낮다 — 그래서 n² 이 아니라 n log n 이 된다.
선형성으로 다 더한다

𝔼[C] = Σi<j 2/(j−i+1) = 2(n+1)Hn − 4n   (Hn = 1 + 1/2 + … + 1/n, 조화수)

Hn ≈ ln n 이므로   𝔼[C] ≈ 2n ln n = 1.386 · n log₂n
2 ln 2 = 1.3863 이 그 상수다. 병합 정렬(n log₂n)보다 비교를 39% 더 하지만, 한 번의 비교가 싸고 추가 메모리가 없어 실제로는 더 빠른 경우가 많다.

5. 최악의 경우 — 평균만 믿으면 안 되는 이유

퀵 정렬의 평균은 훌륭하다. 그런데 pivot 을 늘 첫 원소로 고르면 이미 정렬된 배열에서 최악이 된다. 매번 한쪽이 텅 비어 재귀가 n 단계까지 내려간다.

정렬된 배열 · pivot = 첫 원소 → 비교 (n−1) + (n−2) + … + 1 = n(n−1)/2 — 선택 정렬과 똑같아졌다.
⚠️ 가장 흔한 입력이 하필 최악이라는 것이 고약하다. "거의 정렬된 데이터"는 실무에서 매우 자주 들어온다.

위 시연에서 "정렬된 배열로" 를 누르고 퀵 정렬을 돌려 보라. 비교 횟수가 n²/2 로 뛰는 것이 눈에 보인다.

해결 — 무작위성을 우리가 집어넣는다

문제의 구조 "입력이 무작위다"라고 가정했다
§4 의 유도는 입력 순열이 균등분포라는 전제 위에 있다. 현실의 입력은 균등하지 않다.
해결 pivot 을 무작위로 고른다
그러면 입력이 무엇이든 평균 성능이 보장된다. 무작위성이 입력이 아니라 알고리즘 안에 있게 된다.
⚠️ 이 차이는 생각보다 크다.
· 입력이 무작위라고 가정 → "운 나쁜 입력"이 존재하고, 공격자가 그것을 고를 수 있다
· 알고리즘이 무작위를 만든다 → 어떤 입력에도 기대 성능이 같다. 운이 나쁠 확률은 있지만 입력이 정하지 못한다
이런 알고리즘을 randomized algorithm 이라 한다. Topic 11 (몬테카를로) 에서 이 발상을 정면으로 다룬다.
